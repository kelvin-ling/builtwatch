# Unreadable response recovery — 21 October 2026

A successful HTTP status with an HTML, incomplete JSON, null, array or scalar body was accepted as a successful API response. A malformed session response could silently replace the private workspace view with the demo; a malformed mutation response could look successful.

The browser transport now requires a JSON object for successful API responses and reports an unreadable response otherwise. Refresh checks retain the last private view. The message tells the user to refresh and inspect current state before trying an action again: a lost mutation response is an unknown outcome, and the client does not automatically retry it. Non-success HTTP responses retain status/code and their safe fallback, including when the error body is null or unreadable. Valid explicit signed-out sessions and empty-object mutation results remain supported.
